# Do not report what has already been read

Miles triaged everything from the last two days regardless of whether JJ had opened it. Three
reports in a row on 2026 08 29 led with the same three GitHub notices he had read the day
before. Nothing about them had changed.

The cost was not noise. It was that a Khan Academy unit test due the next day, set on 22
August, sat underneath them and was never seen.

## The rule

Search `is:unread` first. That result is the report.

A read message is one JJ has already looked at, so it stays out, with three exceptions:

1. It has a deadline inside the next seven days.
2. A reply is outstanding **in either direction**. One he owes, and one he sent and has not had
   back, both count. The second kind was dropped on the first attempt and it was a meeting the
   next day.
3. He asked for it tracked.

A carried over item says it is a reminder and gives both dates. `Read 28 Aug, deadline 28 Sep`
tells him why it is back. A silent repeat reads as new mail and costs him the time to work out
that it is not.
