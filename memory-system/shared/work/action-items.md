# Action items

`Projects/ACTION-ITEMS.md` is the list of things only JJ can do. The file itself lives at the
top of Projects, not in here. This is how it works.

- **Append to the bottom.** Never reorder, never edit a line somebody else wrote, never delete
  a ticked one.
- Format: `- [ ] <what to do> · <why it is blocked on JJ> · <source>`
- If the brackets have something inside them, that text is from JJ himself.
- **Do not recite the list in chat.** Say `action items updated` and nothing more. He reads the
  file. Repeating it back is noise he has to scroll past.
- Only put something there if JJ is genuinely the only one who can do it. Work you could do
  yourself does not belong on his list.
- Read it before you report. Anything already ticked is closed, whatever else you found. A
  closed Cursor permissions item kept reappearing in reports for exactly this reason.

## Email things do not go on that list

JJ asked for this on 2026 09 04. A report every two hours was filling his list with RSVPs,
unsent drafts and Drive share requests, and a list that is mostly routine mail is a list nobody
reads to the bottom of. The four that were on it were moved to
`army/olivia/miles/pending.md`.

So: anything that came out of the inbox goes on Miles's own pending list, which `run.sh`
appends to. `Projects/ACTION-ITEMS.md` is for everything else.

Nothing is dropped by this. A needed reply that exists only as a sentence in a report is how
work goes missing, which is the reason any of this exists. It is still written down, it is
still in the report that goes to Slack, and Miles is given both lists in his prompt so he does
not raise the same thing twice.

A line can be moved from one list to the other by hand. They use the same format on purpose,
and the duplicate check reads both, so moving one up to JJ's list does not make it come back on
the next run.
